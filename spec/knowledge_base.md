# Specification: Knowledge Base CLI (`note`)

## 1. Overview & Core Principles

The Knowledge Base CLI is a lightweight, high-performance command-line tool built in Rust (`crates/notes`). It manages a personal and agent-accessible wiki stored as plain Markdown files (`.md`) with YAML frontmatter, following the **Obsidian** linking philosophy.

### Core Principles
- **100% Plain Markdown Storage:** All documentation, guides, architectural records, and notes are stored in `workspace/notes/`.
- **Obsidian Compatibility:** Native support for bidirectional Wikilinks (`[[Note_Title]]`) and cross-referencing tasks (`[[task-001]]`).
- **AI Context Hub:** Serves as the long-term memory, prompts repository, and specification store for LLM agents (Claude Code, Cursor).
- **Fast Full-Text & Tag Search:** Instant substring and metadata filtering across the whole note tree in milliseconds.
- **Dual Output Interface:**
  - **Human Mode:** Formatted tables, trees, and colorized link graphs.
  - **Agent Mode (`--json`):** Machine-readable JSON output on `stdout` with structured search matches and backlinks.
- **Atomic Operations:** All note updates and file creations are atomic.

## 2. Directory Layout & Note Schema

### Recommended Folder Structure

```text
workspace/notes/
├── 00_Inbox/           # Quick ideas, temporary thoughts, unorganized captures
├── 10_Projects/        # Project specifications and scoped feature documentation
├── 20_Wiki/            # Permanent architecture decision records (ADRs), guides, standards
├── 30_Prompts/         # System prompts, agent rules, and execution templates
└── 40_Reports/         # Automated execution summaries and benchmark reports generated by agents
```

### Note File Schema

Every note is saved as a `.md` file (e.g., `workspace/notes/20_Wiki/auth_architecture.md`):

```markdown
---
title: Authentication Architecture
tags:
  - auth
  - security
  - jwt
aliases:
  - Auth Spec
  - Token Auth
created_at: 2026-09-03
updated_at: 2026-09-03
---

# Authentication Architecture

Detailed specification of the token-based authorization scheme.

## Design Decisions
1. Use Ed25519 signatures for asymmetric verification.
2. Store refresh tokens in secure storage.

## Connections
- Implements: [[task-001]]
- Related: [[database_schema]]
```

### Frontmatter Fields

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `title` | `String` | Yes | Human-readable title of the note. |
| `tags` | `List[String]` | No | Topic or category tags (e.g., `[auth, rust]`). |
| `aliases` | `List[String]` | No | Alternative titles for Wikilink resolution. |
| `created_at` | `String` | Yes | ISO 8601 creation date (`YYYY-MM-DD`). |
| `updated_at` | `String` | No | ISO 8601 modification date. |

## 3. CLI Commands

### Global Options

```text
--json                   Machine-readable JSON output
--workspace <PATH>       Custom path to workspace notes directory (auto-discovered if omitted)
-q, --quiet              Suppress informational output
-h, --help               Print help information
-V, --version            Print version information
```

### Command Reference

#### 1. `note list` (alias: `ls`)
List all notes or inspect a specific subfolder.

```bash
note list [FOLDER] [OPTIONS]
```
- `[FOLDER]`: Optional folder prefix (e.g., `20_Wiki` or `00_Inbox`).
- `-t, --tag <TAG>`: Filter notes by tag.
- `--tree`: Display as a visual directory tree.
- `--json`: Emit an array of note summaries in JSON.

#### 2. `note new` (alias: `add`)
Create a new note with initialized YAML frontmatter.

```bash
note new "<TITLE>" [OPTIONS]
```
- `-f, --folder <FOLDER>`: Target folder (default: `00_Inbox`).
- `-t, --tags <T1,T2>`: Comma-separated tags.
- `-c, --content "<TEXT>"`: Initial markdown body text.

#### 3. `note show <QUERY>` (alias: `view`)
Display the contents and metadata of a note.

```bash
note show <QUERY> [OPTIONS]
```
- `<QUERY>`: Note title, filename, or relative path (e.g., `auth_architecture` or `20_Wiki/auth_architecture.md`).
- `--raw`: Print raw file content without CLI decoration (ideal for pipes: `note show auth --raw | grep ...`).
- `--json`: Emit full note object with parsed outgoing links and metadata.

#### 4. `note search <QUERY>` (alias: `find`)
Full-text search across titles, content, and tags.

```bash
note search "<QUERY>" [OPTIONS]
```
- `-t, --tag <TAG>`: Narrow search to notes with specific tag.
- `--json`: Output matched notes with snippet lines.

#### 5. `note links <QUERY>`
Inspect connections (outgoing links and backlinks) for a note.

```bash
note links <QUERY> [OPTIONS]
```
- Lists all outgoing `[[...]]` links inside this note.
- Lists all backlinks: other notes or tasks that point to this note.

#### 6. `note append <QUERY> "<TEXT>"`
Append text to the end of a note without opening an editor.

```bash
note append 00_Inbox/ideas.md "Consider adding OAuth2 PKCE flow."
```

#### 7. `note edit <QUERY>`
Open the target note in `$EDITOR` (or `vim`/`nano`/`code`).

```bash
note edit 20_Wiki/auth_architecture.md
```

#### 8. `note delete <QUERY>` (alias: `rm`)
Delete a note file.

```bash
note delete 00_Inbox/obsolete.md -y
```
- `-y, --yes`: Bypass confirmation.

## 4. Agent Integration Protocol (Claude Code)

### Exit Codes
- `0`: Success.
- `1`: Note not found, validation failure, or file I/O error (written to `stderr`).
- `2`: Invalid CLI syntax or arguments.

### JSON Output Schemas

`note search "auth" --json`:
```json
[
  {
    "path": "20_Wiki/auth_architecture.md",
    "title": "Authentication Architecture",
    "tags": ["auth", "security", "jwt"],
    "matches": [
      {
        "line_number": 12,
        "content": "Implement token-based authentication using Ed25519 signatures."
      }
    ]
  }
]
```

`note links "auth_architecture" --json`:
```json
{
  "note": "20_Wiki/auth_architecture.md",
  "outgoing_links": [
    "task-001",
    "database_schema"
  ],
  "backlinks": [
    "workspace/tasks/task-001.md",
    "workspace/notes/10_Projects/mvp_plan.md"
  ]
}
```

## 5. Typical Multi-Agent Workflow

```text
1. [Claude Code] Searches context:
   $ note search "database schema" --json

2. [Claude Code] Reads the full specification:
   $ note show database_schema --raw

3. [Claude Code] Completes implementation and creates a task:
   $ task add "Implemented migration" -s done -l db

4. [Claude Code] Writes an execution report to the knowledge base:
   $ note new "Migration Report 2026-09-03" -f 40_Reports -t db,report \
       -c "Successfully applied migrations. Linked to [[task-004]]."
```
